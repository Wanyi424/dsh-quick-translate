# 快捷翻译 · DSH 插件

独立的中英文翻译页面。使用 DSH 已配置的模型，翻译行为完全由提示词决定；没有语言检测服务、语言选择参数、Agent、工具调用或会话交互。

## 安装

适配当前检查的 Windows 桌面版 DeepSeek Harness `0.2.0-rc.2`，与 [Markdown 笔记插件](https://github.com/Wanyi424/dsh-markdown-notes)独立。克隆本仓库后，按下方「开发与验证」构建安装包。

在 DSH 左侧「插件」页面选择「添加插件」，添加压缩包：

```text
dist/dsh-quick-translate-0.1.3.tgz
```

按安装页面提示启用或重启后，左侧出现「快捷翻译」。无需修改 DSH 的配置文件，也不需要另填 API Key。新插件不会修改笔记插件或已有笔记。此项目没有自动安装到用户的 DSH profile。

## 使用

1. 在「翻译模型」选择 DSH 中已经配置的模型。刚在 DSH 设置里修改模型时，点击旁边的刷新按钮。
2. 输入或粘贴原文，点击「开始翻译」，或按 `Ctrl + Enter`。
3. 译文逐步显示；连接、模型思考、翻译、完成和中断状态分别显示。点击复制获取原文格式的译文文本。
4. 切换到 DSH 的其他页面，后台任务继续。返回翻译页面可恢复进度。点击「停止翻译」保留已输出部分。
5. 左侧历史列表可随时查看；「用原文新建」用于修改后重译。右上角「…」可查看当次提示词、删除记录或打开资源管理器。历史列表底部可确认后清空全部记录。

默认提示词随插件保存在 [prompts/default.md](prompts/default.md)。提示词为普通文本，不插入语言参数或模板变量。模型请求只包含当次提示词和待翻译原文，不带其他翻译历史或 DSH 对话。文档中的多语言规则交由模型理解；其中针对上一条译文的连续反馈规则仍保留原文，但本版本不提供多轮上下文。

在「翻译设置」中编辑后，点击「保存自定义提示词」，自动生成或更新独立的 Markdown 文件：

```text
%USERPROFILE%\.dsh\plugin-data\dsh-quick-translate\prompts\custom.md
```

「恢复默认提示词」立即切回包内默认文件，不改写或删除 `custom.md`；点击「使用已保存的自定义」可以切回。修改只用于之后发起的翻译，正在运行的任务和历史记录继续使用各自的提示词快照。改变模型不会改写提示词文件。

设置页显示默认文件、自定义文件的完整路径，并可打开自定义提示词目录。默认文件位于插件安装目录中的 `prompts/default.md`，以设置页显示的实际路径为准。自定义文件只有首次保存时才创建。请通过自定义文件修改规则，不要编辑包内默认文件。

设置文件只保存当前使用默认还是自定义，不存储提示词正文；历史记录保留当次提示词正文用于回看。当前仍在开发阶段，本版本不读取或迁移旧的 `.dsh-quick-translate` 和 `Documents/DSH Translations` 数据，已移除旧版提示词兼容逻辑。

原文和译文以文本显示，保留换行及 Markdown 源码，便于准确复制。本插件不包含笔记插件的图表或 Markdown 预览引擎。

## 历史记录与迁移

所有工作区共用一套翻译历史，默认在：

```text
%USERPROFILE%\.dsh\plugin-data\dsh-quick-translate\history
```

代码使用 DSH 官方 `@deepseek-ai/dsh-home-paths` 路径库解析根目录，优先跟随 `DSH_HOME`，未设置时使用当前用户的 `.dsh`。`plugin-data/dsh-quick-translate` 是本插件在 DSH 数据根目录中使用的独立子目录，文件仍保持普通 JSON / Markdown 格式。界面底部始终显示实际路径；「… → 在资源管理器打开」打开当前目录。

从 0.1.2 起，历史记录和自定义提示词的目录打开统一使用 DSH 原生 `open-in-app/open` 接口。插件 Host 提供实际目录，桌面宿主负责启动资源管理器；不再隐藏启动 Explorer 并仅凭进程创建判定成功。迁移后打开新目录，原生接口不可用或启动失败会显示错误。升级后请完整退出并重新启动 DSH，使前端和 Host 同时更新。

每次翻译单独保存为 UTF-8 JSON 文件，包含原文、译文、时间、模型提供方、模型名称、当次提示词、状态和错误信息。模型开始调用前先保存输入；流式期间最多每约 2 秒保存一次进度，结束或停止时立即保存。异常退出最多可能丢失最近一段尚未保存的输出；重启后未完成的记录标记为中断，不会自动再次发起付费请求。

「更改位置」或「… → 历史记录保存位置」可输入绝对路径，也可在支持原生目录选择器的桌面环境中选择文件夹：

- 复制本插件管理的记录，确认复制未遇到文件变化，持久化新位置后再清理旧副本。
- 目标已有同名记录时停止；提交配置失败时回退复制，不删除原记录。
- 旧目录为空才删除整个文件夹；存在其他文件或子目录时保留并提示，绝不递归删除旧目录。
- 不能选择相同目录的父子路径、磁盘根目录、用户主目录、符号链接或联接点。
- 正在翻译时需先完成或停止，再迁移或清空，以免产生含糊的记录归属。

模型、提示词及目录设置单独保存在：

```text
%USERPROFILE%\.dsh\plugin-data\dsh-quick-translate\settings.json
```

迁移只移动历史文件，设置与自定义提示词不放在会被删除的旧历史目录里。清空历史不会清空设置或自定义提示词。

## 性能与边界

- Client 启动入口约 12 KB，页面按需加载约 40 KB；复用宿主 React，无 Markdown、图表、编辑器或模型 SDK 大包。
- 未打开页面时不请求模型目录、不扫描历史、没有插件轮询。翻译期间页面订阅推送；隐藏页面断开订阅，后台继续任务。
- 文本增量最多约每 80 ms 合并推送；慢客户端只接收最新进度，避免无限堆积。没有每个 token 的磁盘写入或 Markdown 全文重渲染。
- 历史每页 25 条，只读取当前页的记录内容；列目录仍与文件数量相关。极大量历史应定期清理。
- 一次运行一个任务；原文最多 60,000 字符，提示词最多 16,000 字符，译文最多 240,000 字符，单次最长 10 分钟。模型自身的上下文和输出限制可能更低。
- 使用 DSH 现有模型服务，会占用所选模型的额度或产生其正常费用；插件不会发起后台自动翻译或自动重试整篇翻译。宿主自身的模型重试策略仍然适用。
- 停止和卸载会通知适配器取消请求；提供方是否立即停止计算取决于其实现。关闭 DSH 后任务不继续。
- 不承诺零资源占用。隔离短文本验证未出现超过 50 ms 的主线程长任务，不代表真实 DSH 长文本与所有模型下的性能结果。

## 开发与验证

```powershell
npm install
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run check:browser
npm pack --pack-destination dist
```

构建产物采用 DSH 原生 Client 模块加载器与 `require.async('./client.page.js')`。Host 注入 `connection` 和 `llm`，用 `ctx.llm.listProviders()`、`listModels()` 和 `stream()` 调用模型；不导入宿主内部 UI 组件，不添加 Agent 工具，不改写 profile。

本次执行类型检查、19 项自动化测试和构建，覆盖 DSH_HOME/default 根目录、自定义提示词和设置归属、记录迁移及重启、默认文档读取、自定义 Markdown 保存、恢复默认与切回，以及原有流式输出、取消、后台继续/重连、失败状态、保存失败重试、提示词快照、迁移回退、同名冲突、文件保全、单条删除/清空。目录打开覆盖两个按钮、中文及空格路径传递、迁移后的路径、原生接口错误与不可用提示。此前已通过隔离 Playwright 的浅深色和窄屏验证；本次未改页面结构，因此未重复运行浏览器测试。隔离验证使用真实构建界面及 Host API，但模拟模型提供方和 DSH 原生目录打开接口。
